# V0.6.1 AI 运营助手聊天窗口 — 详细设计

## 一、目标

实现一个可对话的 AI 助手：运营人员用自然语言查询车队状态、异常、已有预测，AI 通过 Tool Calling 调用只读工具获取真实数据后回答。本版本**只读、不自动执行**，保留 Human-in-the-loop 原则。

## 二、核心架构

```
Vue「AI 助手」页
   │ REST
   ▼
ChatController (/api/chat/...)
   ▼
AiChatService（编排：持久化转录 + 调 ChatClient）
   │
   ├── 持久化转录 ──▶ chat_sessions / chat_messages（user/assistant 文本，仅供 UI 回看）
   │
   └── LLM 上下文 ──▶ ChatClient
                        ├ defaultSystem(助手提示词)
                        ├ defaultTools(FleetOpsTools)      ← @Tool 只读方法
                        └ MessageChatMemoryAdvisor(ChatMemory)  ← 内存多轮上下文，按 sessionId 隔离
                             ▼
                        FleetOpsTools ──▶ 现有 Vehicle/Incident/DailyForecast Service
```

### 关键设计决策

1. **LLM 上下文与 UI 转录分层**：多轮对话 + tool 结果回填由 Spring AI `ChatMemory`（内存）管理，不用自己攒 history。DB 只存「给前端回看的文本转录」，**不重建 LLM 的 tool 消息图**（一个 assistant 消息可带多个 tool call，DB 建模它吃力且没必要）。
2. **工具通过 `ChatClient.Builder.defaultTools(fleetOpsTools)` 注册**，不是每次调用时传 `Object tools`。
3. **每会话隔离**：调用时 `.advisors(a -> a.param(ChatMemory.CONVERSATION_ID, sessionId))`，`ChatMemory` 按 sessionId 分桶。
4. **V0.6.1 工具全部只读**：`queryForecast` 只查已有 `daily_forecasts`，不调用 `generate()`（生成预测留在需求预测页 / V0.6.2）。
5. **AI 调用失败不拖垮业务**：`sendMessage` 内 try/catch，失败返回友好提示文本并照常落库。

## 三、数据模型（仅 UI 转录）

```sql
chat_sessions(id, title, created_at, updated_at)
chat_messages(id, session_id, role[user|assistant], content, created_at)
```

- `title` 取首条用户消息前 20 字。
- 不存 `tool_calls` / `tool_call_id`。

## 四、后端组件

| 组件 | 说明 |
|---|---|
| `ChatSession` / `ChatMessage` 实体 + Mapper + IService | 转录持久化 |
| `FleetOpsTools` | `@Component`，4 个 `@Tool` 只读方法 |
| `AiChatService` + `AiChatServiceImpl` | 编排：建会话、发消息、拉历史、删会话 |
| `ChatController` | `/api/chat/**` REST 接口 |
| `ChatSendRequest` DTO | 发送消息请求体 |

`ChatMemory` 直接注入 Spring AI 自动装配的 `MessageWindowChatMemory` Bean，无需自定义。

## 五、工具清单（只读）

| 工具 | 说明 | 返回 |
|---|---|---|
| `queryVehicles(area?, status?)` | 按区域/状态查车辆 | 数量 + 状态分布 + 车辆编号 |
| `queryIncidents(status?, severity?)` | 查异常事件 | 数量 + 状态分布 |
| `queryForecast(date, timeRange?)` | 查已有预测（只读） | 各区域预测订单 |
| `queryWeather(city, date)` | 模拟天气 | `晴/多云/小雨`（标注模拟） |

## 六、接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/chat/sessions` | 新建会话 |
| GET | `/api/chat/sessions` | 会话列表（按 updated_at 倒序） |
| GET | `/api/chat/sessions/{id}/messages` | 历史消息 |
| POST | `/api/chat/sessions/{id}/messages` | 发送消息（body: `{content}`） |
| DELETE | `/api/chat/sessions/{id}` | 删除会话 |

## 七、前端

`/ai-assistant` 页面：左侧会话列表（新建/切换）+ 右侧消息气泡 + 输入框（Enter 发送）。

## 八、明确不做 / 延后

- 详细 tool 调用过程可视化（V0.6.1 只展示最终回答文本；折叠展示工具调用留到后续）
- 流式输出（SSE）
- RAG 知识库、执行类工具（`createDispatchSuggestion`）→ V0.6.2
- 真实天气 API
- 跨重启的 LLM 上下文持久化（当前 ChatMemory 在内存，重启即丢；真持久化 V0.6.2 接 Spring AI `JdbcChatMemory`）

## 九、决策记录

入口=独立页面；天气=mock；知识库=MySQL 全文检索（V0.6.2）；会话=转录长期保存在 DB（可回看），但多轮对话上下文在内存、后端重启后丢失（真持久化留 V0.6.2）。
